## 役割

Tier2/3 判定者向けの構造化ルーブリック。共同研究者レビュー指摘(1)で追加された5項目を扱う。
`interpretation.md` / `generalizability.md` と同じく、**判定を機械化するものではなく、
判定者間の再現性を担保する**ためのもの。

> **重要（両レビューの一致点）**: ここに挙げた5項目のうち、**硬い規則で自動 FAIL にして
> よいものは無い**。節の境界・語句・桁数を機械規則で断ずると、正しい原稿を落とす
> （具体的な反例は各項目に記載）。判定者は必ず該当箇所の文脈を読むこと。

各観点は **PASS / REVISE / INCOMPLETE** で返す。INCOMPLETE は該当セクション本文が
供給されなかった場合であり、PASS の代用にしてはならない。

## 判定観点

### 観点1: Methods 内容の Introduction 混入

**見るもの**: Introduction が「背景・先行研究のギャップ・本研究の目的」に留まっているか。
自研究の手続き（解析モデル、変数定義、除外基準、ソフトウェア）の記述が入り込んでいないか。

**REVISE の例**: Introduction に「多重ロジスティック回帰で年齢・性別・収入を調整した」と
実装詳細が書かれている。

**PASS にすべき例（誤判定しやすい）**:
- 「本研究では年次パネルデータを用いた」——デザインの予告は、研究ギャップを明確にする
  ために正当であり Methods 混入ではない。
- 先行研究の手法への言及（「Smith らはクロスセクション設計を用いたため因果の向きが
  特定できなかった」）——これは背景であって自研究の手続きではない。

**判定基準**: 「読者が Methods を読まずにこの文だけで本研究の手続きを再現できてしまうか」。
再現できる粒度なら REVISE、デザインの一文予告なら PASS。

### 観点2: Results への解釈文の混入

**見るもの**: Results が観察された数値の報告に留まっているか。因果・機序・臨床的含意の
解釈が混ざっていないか。

Tier1 の `check_o_overstatement`（因果含意語のサーフェシング）が候補箇所を機械的に
洗い出して渡してくるので、**判定者はその箇所を精査して最終判定する**。

**REVISE の例**: 「失業者で K6 が高かった。これは経済的困窮が心理的苦痛を引き起こす
ことを示している。」——後半は Discussion の内容。

**PASS にすべき例（誤判定しやすい）**:
- 「K6 は高得点ほど心理的苦痛が強いことを示す」——尺度の読み方の説明であり、
  結果の解釈ではない。読者が数値を読むために必要。
- 「調整後も関連は減衰しなかった」——数値パターンの記述であって因果の主張ではない。

**判定基準**: その文を削っても数値の意味が読者に伝わるか。伝わるなら Discussion へ移す
（REVISE）。削ると数値が読めなくなるなら PASS。

### 観点3: 調査項目の実文言引用（逐語性）

**見るもの**: 原稿が調査項目を引用符付きで示している場合、その文字列が調査票の設問文と
**逐語一致**しているか。

> **注意**: 逐語引用そのものは欠陥ではない。むしろ測定の同定と再現性のために推奨される。
> 判定するのは「**逐語として提示されたものが実際に逐語か**」であって、引用の有無ではない。

**REVISE の例**: 原稿が「過去30日間にどのくらいの頻度で神経過敏に感じましたか」と
引用しているが、調査票の実文言は「この30日間に、どれくらいの頻度で神経過敏に
感じましたか」だった（言い換えを逐語として提示）。

**PASS の例**: 引用符を使わず「神経過敏の頻度を尋ねる項目」と要約している。
要約であることが明示されていれば逐語一致は要求されない。

**設問票が機械可読な場合の機械化**: 一次ソース（設問票の原文ファイル）が
存在するため、引用符内文字列の NFKC 正規化＋空白畳み込み後の**厳密一致**照合は
決定的に実装可能である。fuzzy match は導入しない（曖昧一致は「決定的」の看板を壊す）。
generic プロファイルは ground truth が無いため INCOMPLETE として本 Tier2 判定に回す。

### 観点4: Limitations の書き方

`generalizability.md` 観点2 と重複するため、**本観点では書き方のみを扱い、
一般化可能性の実質判断はそちらに委ねる**（二重計上を避ける）。

**見るもの**:
1. 各限界に**方向と大きさ**が付いているか（「選択バイアスがある」ではなく
   「健康な回答者が残存しやすいため関連は過小評価の方向に偏る可能性がある」）。
2. 汎用テンプレ文で埋めていないか（「一般化可能性には限界がある」だけの一文）。
3. 挙げた限界が結論のトーンに反映されているか（限界を認めながら Conclusions で
   断定している、という不整合が無いか）。
4. 本研究固有の限界か、どの観察研究にも当てはまる一般論か。

**REVISE の例**: 限界が3文とも「〜may be limited」で終わり、どれも方向を述べていない。

**PASS の例**: 限界が固有かつ方向付きで、Conclusions のトーンがそれに整合している。

### 観点5: 数値の桁・精度

**見るもの**: 同一の量が Abstract・本文・表・図注で**同じ桁数**で報告されているか。
p 値・効果量・割合の表記が投稿先/SAP の宣言規則に沿っているか。

> **自動 FAIL 禁止（Codex Sol の反例）**: 一律の精度規則は正しい表記を落とす。
> 正しい `p<0.001`、年齢の1桁表記、OR の2桁表記はいずれも妥当である。桁数を機械判定
> してよいのは、**SAP/config に表記規則が宣言されている場合の、その規則との照合のみ**。
> 宣言が無ければ INCOMPLETE とし、判定者が投稿先規定に照らして判断する。

**判定基準**:
- 同一量の桁が箇所によって違う（Abstract で OR 1.5、本文で 1.52、表で 1.518）→ REVISE。
  これは転記経路の綻びのサインでもあるため、`results.json` からのレンダ経路を確認する。
- 有効数字が推定精度を超えている（N=50 の割合を小数第2位まで）→ REVISE。
- 宣言規則が無く、表記が一貫している → PASS。

**将来の決定的化**: 全数値は `results.json` からプレースホルダ経由で挿入されるため
（SKILL.md §3）、表記規則を宣言化すれば `pipeline/render.py` のフォーマッタで
機械強制でき、この観点は Tier1 に降ろせる。現時点では未実装であり Tier2 に留まる。


## 判定基準

各観点を **PASS / REVISE / INCOMPLETE** で評価する。

- **PASS**: 節の役割分担が保たれ、逐語引用として提示されたものが逐語であり、限界が方向付きで
  書かれ、同一量の桁が全箇所で一致している。
- **REVISE**: 上記のいずれかが崩れている。該当文と推奨表現を具体的に示す。
- **INCOMPLETE**: 該当セクション本文が供給されず照合不能。**サイレント PASS 禁止**で
  人間ゲートへ surface する。
- 重み: 本ルーブリックの5観点はいずれも原則 MAJOR（読者を誤導するが結論の識別自体は
  別問題）。ただし観点3の逐語不一致が測定の同定を壊す場合、および観点5の桁不一致が
  `results.json` からのレンダ経路の綻びを示す場合は、それぞれ check A / check C の
  問題としてクリティカル扱いで人間直行を検討する。

## 出力

各観点につき `{観点, 判定(PASS/REVISE/INCOMPLETE), 根拠(該当文), 推奨(修正案)}` を
構造化して返し、総合判定を一つ付す。原稿は書き換えない（是正は工程6）。
verdict は `audit.external.aggregate.aggregate_finding` に渡す。
