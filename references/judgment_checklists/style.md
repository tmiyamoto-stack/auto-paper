## 役割

Tier2/3 判定者向けの構造化ルーブリック。Tier1 の `check_s_style`（check_id "S",
`t1.style.ai_phrases`, MINOR・非ブロック）が洗い出した候補箇所を受け取り、
**文脈で判定する**のが本ルーブリックの役割。

### 前提（判定者が必ず踏まえること）

- check S のヒットは「そこに定型表現がある」という事実に過ぎず、**欠陥の確定ではない**。
- **AI が書いたかどうかを判定しない。** 帰属判定は機械的にも定性的にも証明不能であり、
  本スキルの管轄外。判定するのは学術散文としての質のみ。
- **AI 検出器の回避を目的にしない。** 投稿先が AI 利用の開示を求める場合、開示は
  別途行われるべき事項であり、文体の推敲とは無関係。
- 辞書の出典と取り込み範囲は `references/style_lexicon.md` を参照。

各観点は **PASS / REVISE / INCOMPLETE** で返す。

## 判定観点

### 観点1: 定型語彙が文脈上不自然か

check S のヒット箇所それぞれについて、その語が**具体的な内容を担っているか**を見る。

- REVISE: 「本研究は多面的な影響を包括的に検討し、重要な示唆を与える」——具体が無く、
  どの節にも貼り付けられる文。
- PASS: 「多面的介入（運動・栄養・睡眠の3要素）を評価した」——「多面的」が具体を指している。

**判定基準**: その語を削って具体的な記述に置き換えられるなら REVISE、
削ると意味が失われるなら PASS。

### 観点2: 同義語循環（term consistency）

同一の構成概念が節をまたいで別語で呼ばれていないか（"patients" / "participants" /
"subjects" / "individuals" の循環、"association" / "relationship" / "link" の循環）。

医学論文では**同じ概念は同じ語で呼び続ける**のが正しい。専門用語の反復は良い科学文章の
特徴であって欠陥ではない。

- REVISE: 同一コホートが3段落で3通りに呼ばれている。
- PASS: 用語が一貫している（反復が多くても PASS）。

check S は語彙辞書のマッチのみを行い、この観点は検出しない（文脈追跡が要るため）。
判定者が本文を読んで判断する。

### 観点3: 多層ヘッジと内容希薄な評価文

- 多層ヘッジ: 「〜の可能性が示唆されるかもしれないと考えられる」のように推量が重なる。
  1段のヘッジに畳む（REVISE）。
- 内容希薄な評価文: 「本研究の意義は大きい」「重要な一歩である」など、削っても情報が
  失われない文（REVISE）。

**PASS にすべき例**: 単語レベルの学術的接続（"Notably," "Importantly," "Additionally,"）は
標準的であり、段落あたり1回程度なら削らない。段落ごとに機械的に反復している場合のみ REVISE。

### 観点4: 文リズムと段落結束

- 同じ長さ・同じ構文の文が続いていないか。
- 段落の冒頭が毎回同じ接続詞で始まっていないか。
- 接続詞を削る場合、**素で消さない**こと（論理関係が失われる）。言い換えるか文を再構成する。

これは決定的照合が成立しない領域であり、check S は一切検出しない。判定者の定性判断。

## 判定基準

各観点を **PASS / REVISE / INCOMPLETE** で評価する。

- **PASS**: 定型語彙が具体を担い、用語が一貫し、ヘッジが1段で、文リズムに変化がある。
- **REVISE**: 語を削って具体に置換できる／同一概念が別語で循環している／推量が重なっている／
  内容希薄な評価文がある。該当文と推奨表現を示す。
- **INCOMPLETE**: 原稿本文が供給されず照合不能（check S が `section_texts=None` で
  INCOMPLETE を返した場合を含む）。**サイレント PASS 禁止**。
- 重み: 本ルーブリックは原則 MINOR であり、単独で投稿可否を左右しない。ただし文体の
  問題が主張の曖昧化（ヘッジの多層化で結論が読めない等）に達している場合は、
  `interpretation.md` の管轄へ回す。

## 出力

各観点につき `{観点, 判定(PASS/REVISE/INCOMPLETE), 根拠(該当文), 推奨(書き換え案)}` を
構造化して返し、総合判定を一つ付す。verdict は
`audit.external.aggregate.aggregate_finding` に渡す。

### 修正の実行主体（重要）

本ルーブリックの REVISE は**修正案の提示に留まる**。監査エージェントは原稿を編集できない
（SKILL.md §1「監査と修正の分離」）。実際の書き換えは revision エージェントが行い、
書き換え後は数値プレースホルダの対応・引用の係り先・否定・ヘッジが保存されているかを
再検証する（文リズムの変更でこれらが壊れうるため）。
